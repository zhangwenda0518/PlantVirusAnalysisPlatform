## 二、修复的真实缺陷

### 1. mirna 模块 100% 不可用（依赖探测漏登记）

`Virus_Platform_Core/module_deps.py:63` 声明 `'mirna': ['srna-target']`，但
`Virus_Platform_Core/config.py` 的 `detect_tools()` 候选表里**没有 `srna-target`
这个键**，于是 `tool_status()['srna-target']` 永远为空串 → 永远判缺。
而引擎文件一应俱全（miranda / RNAhybrid / PITA 三套都在 `3rd/tools/srna-target/`）。

**误导性**：报错文案是「缺少必要外部工具」，日志还打了「自动安装插件…」，
把排障方向引向插件源（那里根本不提供）。

**修复**：补探测表条目 + 新增 `_srna_target_complete()`（三引擎**全部**存在才算可用）。
后者是刻意的保守判定：三引擎缺一时 `bin_engines.run_*` 会**静默返回 None** 降级，
共识等级会从 LOW 悄悄变成 VERY HIGH 却不报错——比直接判缺危险得多。

**验证**：`selfcheck` 第②项 32/32 → **33/33**；mirna 端到端 `status=done`，3 秒完成，
产物齐全。

### 2. vp_ascii_root 自引用环（依赖审计 100% 失败）

`main.py selfcheck` 第⑥项报 `FileNotFoundError`，路径嵌套九层、撞 MAX_PATH。

**链路**：`config.ensure_usable_tempdir()` 首行写的是 `if _usable(tempfile.tempdir)`，
而模块**首次导入**时 `tempfile.tempdir` 还是 `None`，`_usable(None)` 直接返回 False
——**哪怕系统临时目录完全可用**，也会落到 `run/tmp` 兜底分支，把
`tempfile.gettempdir()` 永久改到平台根内部。`hmm_annot._ascii_path()` 用它建 junction，
链接就落进了被链接的树自己，形成自引用环。

**关键点**：这不是"罕见兜底"，而是**每次启动都发生**。实测系统临时目录
（`C:\Users\...\AppData\Local\Temp`）根本没问题，代码却主动搬进了平台根。

**修复**：新增 `_sys_tempdir()`，口径改为"显式设置过就用设置的，没设置过就问环境变量要"；
`ensure_usable_tempdir()` 首行改用 `if _usable(_sys_tempdir())`。

**教训**：兜底分支要判"真的不可用"，不能判"我不知道"。`tempfile.tempdir is None`
表达的是"还没问过"，不是"系统没有"。把未知当否定，兜底就会从"万不得已才走"
变成"默认就走"。

> 这条修复有过一次反复：第一版只改了 `_ascii_path()`（建链接前做环检查），
> 当时绿了，一小时后复跑又红——因为根源在 `ensure_usable_tempdir()`，
> 每启动一次就重造一个环。**"修完又回来了"要先怀疑只盖住了症状分支。**

### 3. 4 个工具的空参数提交会建出「必然失败」的任务

32 个工具箱工具里有 9 个输入是"多选一"。实测：

| 工具 | 修复前 | 修复后 |
|---|---|---|
| mirna / kvsuite / genoplot / orfa / phylodyn | 400 + 中文原因 ✔ | 不变 |
| **consensus / kvchain / pdprep / verify** | **建任务 → 终态 failed** ✘ | **400 + 中文原因** ✔ |

**后果**：用户看到一张 `pct=1`、`status=failed` 的卡，真正的文案埋在任务 error 里；
每试一次多一个空转任务目录。

**根因**分两类：
- `verify`/`consensus`/`pdprep`：校验写在 **job 体**里（`raise ValueError`）。
  任务线程没有 Flask 请求上下文，`abort(400)` 会退化成没有文案的 400，
  所以当初改用了 `raise ValueError`——但**任务已经建出来了**。
- `kvchain`：它是 kvsuite 的 `stage=all` 封装，schema 直接复用 kvsuite，
  自己不做入口校验，指望 kvsuite 在任务线程里 abort。

**修复**：4 个 job 函数的 **factory 期**（`return job` 之前）补与 kvsuite 同款的
互斥校验。`chains.py` 的 kvchain 单独补（它在另一个模块）。

**验证**：9/9 全部 400 带中文；MCP 侧同样被拦（共用同一 factory）；
**反向验证**：把 `abort` 换成放行桩后 4 个工具立刻从 400 变 500，
证明新校验是唯一的那道闸，测试不是蒙对的。

### 4. AI 工作台会话历史：8 个 i18n 键缺失（英文界面显示中文）

`_audit_contract.py` 报 8 个 `ai.dock.*` 键被代码使用但字典未定义：
`partial` / `clearConfirm` / `noConvs` / `untitled` / `msgsN` / `current` /
`newConv` / `switchBusy`。

代码里每个调用点都写了中文兜底（`t('ai.dock.noConvs', '还没有别的会话')`），
所以功能不崩，但**切到英文这 8 处仍显示中文**。整组只加了一半。

**修复**：按代码里的中文原文补齐中英双语。

### 5. i18n 字典重复键（静默死代码）

`tests/_check_i18n.py` 报 4 处重复键，全部是早前补键时自己造的：
`se.savedAiFail` / `ui.qs.switchBack` / `ai.act.interrupted` / `anc.verifyTip2`。

**为什么难发现**：同一对象内重复键**不是语法错误**（`node --check` 是绿的），
后写的静默覆盖前写的，前一处变成永远执行不到的死代码，页面也照常显示。

其中 `anc.verifyTip2` 两处**内容还不一致**（`\'` vs `\u2019`），是两次独立编辑的残影。

**修复后**：`模板锚点 1411 个全部有定义，中英成对，无重复键`。

### 6.（早前一轮）archive / purge 空 POST 就能删数据

`POST /api/tool/runs/archive` 的 `keep` 缺省 3 就生效、`POST /api/tool/runs/archived/purge`
的 `names` 省略 = 清空归档区。已加 `{"confirm":"archive"}` / `{"confirm":"purge"}` 令牌，
并登记进 `tests/_audit_routes.py` 的 `DESTRUCTIVE_POST`。

> 这一条是我自己在探测时踩爆的：我在 `tmp_diag/` 写了"空 POST 巡检"脚本，
> **照抄了巡检的思路却没照抄跳过表**，删掉了 74 个历史工具箱运行目录
> （`run/results/`、`run/tasks/`、数据库、源码均未受影响）。

### 7.（早前一轮）AI 工作台 result_sample 契约、dsrna PLATFORM_ROOT NameError 等

- `executors.py` 把 create_sample 的样品名写进 `tid`，会让 AI 的 wait_task 空转到超时；
  `_snapshot()` 白名单也漏了该字段（刷新页面丢样品名）。已改契约并同步前端 + i18n。
- `dsrna_pipeline.py:147` 用了未导入的 `PLATFORM_ROOT`，只在未登记工具路径时才走到。已修。

## 六、遗留与建议

1. **可选依赖缺失**（不影响核心功能，对应功能自动降级）：
   `gget`（部分在线查询）、`playwright`（`3rd/python` 里没有，浏览器用例需 `C:\Python312`）、
   `tkinterdnd2`（拖拽上传）。
2. **数据损失说明**：我在探测中误删了 `run/tool_runs/` 下 74 个历史工具箱运行目录
   （2026-10-12 ~ 10-26）。样品结果、任务记录、数据库、配置均完好。
   接口已加固（confirm 令牌 + 巡检跳过表登记），同类事故不会再发生。
3. **建议**：`tests/_run_all.py` 增加"检测到 8765 上有多个实例就拒绝启动"的守卫，
   从根上避免并发假红（本轮至少 3 次假红源于此）。
