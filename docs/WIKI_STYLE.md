# Wiki 模块文档写作规范（WIKI_STYLE）

> 适用于 `wiki/*.md`（组概览「模块说明」的内容源）。目标：**每篇模块文档都有一致的三级结构**，
> 目录栏（组概览右侧粘性目录）在任何一篇里都能展开出 一级模块 → 二级节 → 三级子节。
> 本规范由 2026-11-05 全量重审引入；改文档必须遵守，`dev_tools/sync_wiki.py` 同步到静态副本。

## 0. 文档分类与骨架

### 0.1 模块专页（对应组内每张卡/页面，约 45 篇）
必须使用以下 **H2 骨架与顺序**（节的标题文字固定，不得改名）：

```
# <Slug> · <中文模块名>

> 返回 [Home](Home) ｜ 上一页：[X](X) ｜ 下一页：[Y](Y)

（导语 2–4 行：模块回答什么问题、输入是什么、输出是什么。
 再两行：对应引擎 `…`；工具卡 `t-xxx` / 页面 `/xxx`；操作目录 id `xxx`。
 不要写「一句话定位：」「对应引擎：」之外的元标签前缀。）

## 输入
### 输入格式
### 参数

## 流程
### 步骤一 / 模式一 …
### 步骤二 / 模式二 …

## 产物
### 目录结构（代码块）
### 关键文件与字段（表格）

## 示例输入与输出
### 示例输入（代码块）
### 示例输出（图片 + 图注，或文件清单）

## 界面与 CLI
### 界面
### CLI 与 agent（无 CLI 就写明「本模块无 CLI 子命令，界面与操作目录入口如下」）

## 相关
```

- **硬性要求：至少两个 H2 下各有 ≥2 个 H3**（流程、示例、产物、界面最自然）。三级导航靠它存在。
- 模块特有的 H2（如「参数档」「证据边界」「引擎对比」）只允许插在「流程」与「产物」之间，
  且其下必须有 H3；能并入既有六节的，优先并入。
- 无输入/无示例的模块：相应 H2 可省略，但**不得用别的名字替代**（如「做什么」→ 用「流程」；
  「输出」→ 用「产物」；「示例输出」→ 用「示例输入与输出」）。
- 示例节固定两个 H3：「示例输入」「示例输出」。

### 0.2 组导读（9 篇 `*-Intro` / Public-Data / Compare / Phylodynamics）
```
# <名> · <组中文名>组导读
> 翻页条

（导语：本组回答什么问题，共几个模块；每个模块一篇专页。）

## 模块清单
（有序列表：1. [Slug](Slug) · 中文名 —— 一句定位。每个模块一条。）

## 链路
（一条「A → B → C」的流程线 + 与其他组的衔接一至两句。）
```

### 0.3 全局/知识文档（Home / Quick-Start / Architecture / Pipeline-Overview /
AI-Assistant / CLI-Reference / Settings-Ops / FAQ / Toolbox / Result-Interpretation / Report）
不强制六节骨架；保持现有结构，只做：统一的标题命名、去重、断句、标点与表格规范。
Toolbox 的示例小节用 `###` 分工具。

## 1. 语言规范

- **中文技术文风**：陈述句、短句；一句不超过 60 字，长句拆分。
- **去口语/去代理腔**：删「其实、我们、搞、弄、这边、那边、一句话定位：」；
  不用第一人称；不写自我指涉（「本文」「本页」除外，指代 wiki 页面时可用）。
- **术语统一**（全库同一词）：
  | 概念 | 统一写法 |
  |---|---|
  | 一张工具卡片 | 工具卡 `t-xxx`（不写「卡片」「这张卡」混用） |
  | 模块的输出文件/目录 | 产物（「输出」只用于示例节标题「示例输出」） |
  | 可调项 | 参数（不写「选项/开关」混用；界面上的开关可写「开关」，但表格列名用「参数」） |
  | 计算实现 | 引擎（写文件名 `xx.py`） |
  | agent 接口 | 操作目录 id `xxx` / MCP `vp_run_tool` |
  | 上游/下游 | 上游、下游（不写「上文库」「下游链」等自造词） |
- **去变更史**：正文只写「现在是什么行为」；不写「此前误写」「旧实现」「2026-xx-xx 修正」
  这类变更注记（它们属于 `docs/DEVELOPMENT_NOTES.md`）。版本性的「2026-10-07 实装」等
  若用于区分能力档位可保留，但尽量改写为能力名。
- **不重复**：同一句话/同一段不得出现两次；导语不复述 H2 小节内容。
- **不新增未核实事实**：重组时保留已有事实与数字；不确定的不写。

## 2. 格式规范

- 标点：中文全角（，。；：！？（）「」）；英文缩写与代码用半角。
- 代码/路径/参数名/文件名：一律反引号 `` ` ``。
- 数字：千分位（`6,096 bp`）；百分比 `98.5%`；范围用 `–`（如 `85–95%`）。
- 列表：**步骤用有序列表**（1. 2. 3.）；并列项用无序列表。列表项末尾标点：
  同一条列表内统一（句末都不加句号，或都加；推荐短句不加、完整句加）。
- 表格：`| 列 | 列 |`，表头分割行 `|---|---|`；单元格内不换行；长表格精简列名。
- 代码块：标注语言 ```text / ```bash / ```csv / ```bat；目录树用 ```text。
- 链接：站内 `[Slug](Slug)`；外部完整 URL。
- 图片：`![示例输出：短说明](assets/xxx.png)`；图注单独一行斜体：
  `*图注：这张图怎么看（面板/坐标轴/数值含义）。*`；图片路径与文件名不得改动。
- 幂等要求：改完的文档再次运行同步/渲染无差异。

## 3. 审核清单（每篇改完自查）

- [ ] H1 为 `# <Slug> · <中文名>`，翻页条保留原样（不改 slug/排序）。
- [ ] 模块专页六节标题与顺序符合 §0.1；≥2 个 H2 下有 ≥2 个 H3。
- [ ] 无「一句话定位：」前缀；导语无重复段。
- [ ] 术语与 §1 词表一致；无口语/代理腔。
- [ ] 标点全角、代码反引号、表格对齐、图注斜体格式正确。
- [ ] 图片引用路径未变（`assets/…` 相对路径）；图注描述与图片实际内容一致。
- [ ] 已核实的事实、数字、文件名保留（允许压缩措辞，不得丢关键参数/产物名）。
- [ ] 无「此前/旧实现/2026-xx-xx 修正」式变更史（能力档位名可保留）。
- [ ] 站内链接目标存在（[…](Slug) 的 Slug 在 wiki/ 下有同名 .md）。
